ALT fast-path correctness audit — author notes, 8 October 2026

Conclusion
The replacement of the old high-depth saddle/series shortcut was justified by
numerical failures, including an actual full-Bible component-evidence difference.
It does not establish that online contour integration is necessary. Accurately
precomputed kernels, interpolation, reuse, and native evaluation are independent
ways to recover speed. The user's recollection of a fast permanent-table engine
is consistent with the upstream design.

Scope and evidence
Read-only inspection of source, Git history, existing calibration and saved
profile outputs. This audit recomputed hashes, compared saved count arrays, and
reconstructed the deterministic outer grid; it ran no estimator or numerical
integration, submitted no job, and changed no scientific source or saved run.

Why the route changed
Commit d1e4d2693610595d43434a6079e2162176e3c149 (7 October) deliberately replaced
universal_tables._saddle_row's call to log_phi_column with exact_log_phi_column,
using oversample=8, checked-series tolerance 1e-13 and contour tail 40 nats.
The inherited cutoff saddle_min_depth=54 and private function name were kept;
diagnostics correctly identify the new route as direct-contour. Existing pinned
store files cover depths 2–53. This was not an accidental environment selection.
The initial adapter's hashes match Git revision 6378e36 for depth.py, mellin.py
and universal_tables.py, including the old pilot's recorded implementation hash.

Independent opportunities to recover speed
1. Accurate pretabulation and reuse. U/paper/complexity.tex:311–338 describes
   a permanent exact-formula store, degree-7 interpolation, shared-contour work,
   and guarded build-stride interpolation. These do not require the failed
   saddle/series approximation. ALT already keeps degree-7 interpolation in u
   and degree-11 count-anchor interpolation below 54. Its 111 declared sampled
   anchor rows passed the original 3e-9-nat gate; one L=53,r=0,u=-24 row missed
   the stricter 1e-11 low-count gate at -1.416e-11. Extending accurate tables or
   a persistent cache above 53 is the most direct way to amortize contour work.
   No previously admitted high-depth ALT store was identified in this audit.

2. Native scans/interpolation. ALT's kernel.py explicitly supplies None fallbacks
   to avoid import-time compilation/source writes; depth.py:345–350 also disables
   PMM_INTERP_KERNEL. This is separate from the failed high-depth approximation.
   universal_tables.py:939–945 documents upstream exact-value comparisons of
   2.9 million interpolation values and a repaired historical native defect.
   Those claims are inspected upstream evidence, not a new native-platform test.
   Merely switching the environment flag cannot activate the absent native shim;
   moreover, the current high-depth and ladder branches return before the native
   matrix-interpolation branch. Integration must target the actual hot path.

3. Exact-low-count / asymptotic-large-count hybrids remain candidates, not
   validated replacements. Saved high-depth large-count legacy errors can be
   around 1e-6 nats, above the current 3e-9 row gate. Success for low counts alone
   would not validate such a hybrid. Precomputed corrected kernels avoid that
   approximation question entirely.

Conditions on any replacement
Preserve all declared depths, equal prior weights, samples, targets, endpoints,
family grids, units and normalization checks. Do not recover time by depth-tail
truncation: ALT intentionally evaluates every declared component. A high-depth
store must support the ALT range through 138, count/augmentation coverage,
left tails and upper-window retries through 80; the inherited generic column
interface currently rejects L>70. Validate off-grid/off-anchor values and actual
profile/augmentation/mixture outputs, not only table nodes. Retain the agreed
predictive KL refinement criterion of 1e-5 bits and raw-mass diagnostics; the
1e-3 raw normalization rejection guard is not an accuracy certificate. Pin new
store/source/runtime identities and complete the corresponding calibration and
admission checks before production. Existing records must remain unchanged.

Any new high-depth pretabulation prototype being evaluated concurrently is not
certified by this read-only audit; its numerical and end-to-end checks should be
archived separately. The result here supports rejecting the old approximation,
while actively pursuing exact-kernel table reuse and verified native execution.
