SCITAS n-split scheduling pilot and resource gate

This immutable snapshot contains the reviewed gate, pilot drivers, check fixtures and actual incomplete Linux assessment. It does not claim completed numerical validation or production admission. The earlier all-n pilot and gate remain unchanged in their separate archive.

The 7754-job production plan splits primary benchmarks by n while retaining all original sampling_n_values, target seeds and global trial IDs. Each of the eight heavy pilots uses Zipf 1.5, 20 trials, all 81 depths and one original n. Every saved target/count array is compared exactly with its original all-n pilot array before scoring; copied NPZs and the comparison proof are part of each Run inventory. The scheduling gate independently checks the original and selected NPZ hashes. It excludes only admission.py and distributed.py from computational-source compatibility because the frozen revision changes only admission and job partitioning in that scope.

The gate consumes the five other representative pilots, all eight n-split Runs, corrected full power calibration and late-offset replay records. It requires all pilots to pass, measured RSS below 5 GiB per process and elapsed time below four hours. For primary work it uses the larger of measured heavy per-n time and uniform per-n preparation plus the whole uniform nonpreparation overhead. Every job gets 2x timing headroom plus 60 seconds, and every controller gets a one-hour reserve. It selects the smallest eligible 4/8/16-node count using both modulo controller assignments and a conservative load/72 plus longest-job bound. Each node has 72 CPUs, 440 GiB and 24 hours. These are finite-profile projections with headroom, not universal runtime bounds.

Interface: --plan FILE --repo DIR --pilot-root DIR --nsplit-root DIR --power-root DIR --out NEW_DIRECTORY. Results are written to NEW_DIRECTORY/assessment.json. Missing completed inputs return pending (exit 2), invalid evidence returns failed (exit 1), and only eligible complete evidence returns passed (exit 0). A separate numerical admission gate is required before production.

Nine synthetic checks cover node choices 4/8/16, no eligible count, computational source mismatch, power runtime mismatch, nested replay threads, original sample identity and selected NPZ corruption. Synthetic fixtures are explicitly non-scientific. The actual Linux smoke returned pending because the spectrum result was absent, with the expected production plan hash. At this snapshot the first n-split pilot passed in 1044.735 seconds with 458.0 MiB peak RSS; seven others and the spectrum pilot remained running.

The local-to-SCITAS Bible validation timing proxy flagged risk for the old 12-hour serial calibration. It is a cross-workload estimate, not a measured bound; the coordinator replaced that job with a new 24-hour validation allocation and preserved the partial old run. The production Bible singleton itself measured 1789.045 seconds and 1.63 GiB peak RSS.
