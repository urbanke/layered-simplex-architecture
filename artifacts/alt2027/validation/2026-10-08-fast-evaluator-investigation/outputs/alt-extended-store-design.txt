ALT extended sealed kernel store — read-only design, 2026-10-08

Recommendation

Build a NEW, immutable, versioned store that serves every depth 2–138 by the existing degree-7 interpolation in log(t), with degree-11 interpolation of the gamma-subtracted residual in log(r+1). Keep depths 0 and 1 analytic. Use the corrected contour/series evaluator to construct and independently check the tables offline. Do not restore the old high-depth saddle approximation: its accuracy failure and the cost of recomputing the corrected contour online are separate issues.

The smallest complete route preserves the current scientific model, grids, samples, outer integration, family refinement, and tolerances. It changes only kernel provisioning. Initial engineering can retain the existing Python interpolation path; native acceleration is a separate optional improvement. There is now positive measured evidence that caching the accurate columns makes this practical, but no extended store has yet passed production admission.

Recommended store contract

- Master spacing H=0.02, upper log(t) bound U_MAX=80, explicit supported levels 2–138. The outer integration still begins at 35 and retries at 60/80 when its existing boundary test requires it. Kernel-table spacing and outer-integration spacing are different controls: the latter can refine to 0.0025 or below while querying the same fixed table.
- Preserve dense integer count anchors 0–256. Retain the existing anchor positions above 256 as the first candidate, including eight anchors above the declared largest supported query count. Use every anchor; do not decimate. Factor 0.083071 and degree 11 are a candidate, not an already demonstrated high-depth accuracy guarantee.
- The engine's declared max_count is 915861, but provisioning also requests r+1 and r+2; family planning explicitly includes c through c+3. The kernel validation specification additionally requests r=1045889 at depths 22, 54 and 138. A simple reusable high-depth design therefore covers query counts through at least 1045889 and includes upper padding beyond that. Keeping the engine's scientific max_count unchanged is compatible with a larger internal table domain.
- Use an explicit grid version and metadata-driven H/U_MAX/depth/count coverage. Preserve the v2 reader for the original store. Record actual levels, anchor lists, each column length/start, float format/byte order, builder/settings/source hashes, file hashes and validation-artifact identities. A manifest L_MAX alone is not evidence that those files exist.
- Keep the original anchors_prod completely immutable. Use a separate staging directory and seal only after the planned contents, checksums and validation artifacts are complete. The new store must reject missing columns, unsupported counts, and queries beyond its certified upper bound. Production must never build a column or fall back to a contour computation on a miss.

Smallest implementation changes

1. Store addressing and format
   src/lsa/alt/_vendor/pmwm/universal_tables.py:63–129, 270–299, 533–564, 926–1064.
   Current per-level .bin files concatenate float64 values. Index entries hold (offset in values, length, CRC), not an explicit u origin. column() recomputes column_start_index(L,r); matrix interpolation, native-call arguments and boundary logic all use module-global H/U_MAX. The reader also demands manifest H=.02 and U_MAX=35. Raising a global U_MAX to80 would reinterpret old arrays and fail the old manifest check; it is not an extension mechanism.
   Minimal clean change: give each store immutable grid metadata and pass its grid geometry through column loading/interpolation, including clamped edge stencils, matrix provision and native leftovers. For new-format columns, derive the origin from persisted start/length and U_MAX, then validate consistency. Preserve the legacy address convention for v2. Replace the column() L_MAX70 guard with verified store coverage and require each requested level's files/anchors.

2. Builder
   Existing design reference: /Users/ruediger/Projects/product_model_with_memory/scripts/build_anchor_store.py:59–150, 187–206, 279–338.
   Adapt its explicit anchor plan and single-parent append discipline to the current ALT corrected evaluator. 3. Low-depth data and the u=35 boundary
   Two concrete choices are possible. A uniform U_MAX80 new store is the cleaner complete design, because the current depth calibration also queries u_max40 for stored depths below54. It can initially reuse the old columns through35 and append an offline-built strip35.02…80 in NEW repacked files, preserving the original source-byte hashes in provenance; validate interpolation across the join at35. This preserves the original low-depth numerical data and avoids rebuilding it. Rebuilding all low-depth columns with the corrected offline builder is also valid but is additional work whose runtime is not measured by the high-depth diagnostic.
   Merely copying low-depth files unchanged with per-level U_MAX35 is a smaller production-only prototype, but then its higher-window calibration must use an explicit reference route rather than silently invoking an online contour fallback. Do not label that prototype a uniform all-domain sealed store.

4. ALT routing and upper-window retries
   src/lsa/alt/depth.py:96–153, 279–315, 339–372, 478–506, 568–589; experiments/alt2027/store-candidate.json:113–129.
   The legacy saddle_min_depth=54 now selects the corrected DIRECT contour, skips store-file requirements and makes ensure_columns/build_columns skip those depths. Leaving it at54 would ignore the new tables. Set the new table engine to no substitution cutoff, and replace StoreConfig's hardcoded "stored-column design ends at depth70" restriction with actual verified store coverage. Do not use an artificial cutoff139 solely to evade that check.
   Right-window extension currently depends on direct_contour, so disabling the cutoff would also disable retries at60/80. Permit the same family-wide retries when the selected store certifies the next bound, retaining the30-nat measured right-gap criterion, common grids and spacing refinements. Fail at the same configured cap.
   Remove/guard right-of-table contour fallbacks in log_phi, log_phi_matrix and _interp_leftovers for the sealed production route. Keep them only in an explicitly selected offline/reference evaluator. Diagnostics must identify stored interpolation accurately, and a test should prove that no contour builder/evaluator is called during admitted production evaluation.

5. Left tails and coverage
   column_start_index starts from -8-L*log(r+1), moves left in steps of5 until its small-t certificate is <=exp(-30), then rounds onto the master grid. Consequently the start depends on BOTH L and r; a fixed lower bound such as -60 is insufficient. The diagnostic deliberately used floor((-60-L*log(r+1))/.02)*.02, which is usually farther left than the current certificate-based start.
   Keep the full certified small-t evaluation to the left of each column. The ALT adapter currently disables the historical "return the limiting gamma term after40 nats" shortcut by setting series_tail_nats=None/infinity; its old empirical justification covered only L<=70 and r<=67465. Do not silently reactivate it when extending to138. If a low-tail shortcut is later desired, establish its remainder bound over the new domain first.

Actionable ordering

First implement metadata-aware read-only serving and the no-online-contour contract, plus a small new-format store covering diagnostic cases. Validate the sparse count ladder at high depths before committing to the full anchor grid: if it needs refinement, that directly changes construction cost. Then build/seal the full new store, run numerical admission and measured throughput pilots, and only then select it for the unchanged production campaign. The current experiment source, source stores and cluster jobs were not changed for this design.
