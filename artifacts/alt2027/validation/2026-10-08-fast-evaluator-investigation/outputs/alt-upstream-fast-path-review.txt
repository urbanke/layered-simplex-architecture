Finding
The user's recollection describes the upstream production architecture: online moment rows use a sealed interpolated store through depth 53, then a vectorized order-two saddle/series approximation from depth 54. The ALT adapter deliberately substitutes direct contour evaluation for that latter path after reference-check failures. No alternate native high-depth kernel generator was found. The native C components relevant to this estimator interpolate existing stored values and solve outer-integrand peak locations. A separate C extension handles graphical sparse margins and does not evaluate the product moment function.

This does not mean that upstream evidence avoided every numerical integral: the final one-dimensional evidence integral is still evaluated by gridded trapezoid over resolved peaks. The distinction is online kernel evaluation versus the final evidence integration.

Implications
1. There is no switch-only recovery of a hidden C high-depth interpolation engine. The large change is ALT's replacement of the high-depth saddle approximation with direct contours.
2. Preserve the validated low-depth count ladder. A modest conservative C scalar-stencil adapter is possible; its tested gain is 1.26–1.34x for provisioning only. The more efficient batch-anchor variant gains 1.97–3.21x here but changes last digits (up to 7.450580596923828e-8 nats at r=200000, L=53); it needs component-evidence/prediction checks before acceptance.
3. The promising larger optimization is separate validated high-depth pretabulation/interpolation or reusable exact-row caching. Existing offline strided-builder machinery is a starting point; it is not evidence of validated high-depth interpolants. Store construction, serving runtime, and finite-domain accuracy must be measured separately. Do not restore the previously failing saddle path merely because it is fast.
4. No full-run speedup, cross-platform equality, uniform error bound, or production readiness follows from these microbenchmarks. Existing completed frozen-engine accuracy records remain applicable to that frozen implementation; any accepted numerical-path change requires the corresponding profile/refinement checks.
